## H1 Правила функции

Что функция принимает, возвращает и проверяет:
- **Вход и выход:** Функция `clean_export(source)` принимает исходный `DataFrame` (работая с его глубокой копией `source.copy(deep=True)`) и возвращает кортеж `(clean, quarantine, audit)`.
- **Проверки и обработка по плану:**
  1. По известным числовым `source_row` группирует повторы: проверяет отсутствие конфликтующих версий (`assert len(distinct_versions) == 1`) и удаляет полные дубликаты повторной доставки (`replays = 2`: `source_row` `15` и `16`).
  2. Очищает внешние пробелы в `county_code` через `.str.strip()` (исправляет `"11001 "` в `source_row = 7`).
  3. Переводит `source_row`, `action_taken`, `loan_amount`, `income` в числа через `pd.to_numeric(..., errors="coerce")`, подсчитывая новые ошибки формата `parse_errors` (`raw.notna() & numeric.isna()`).
  4. Проверяет обязательные правила: известный `source_row`, `action_taken` в `{1, 2, 3}`, известная сумма `loan_amount > 0`, `county_code == "11001"`, отсутствие текстового брака в `income` (исходные пропуски `income` допустимы).
  5. Разделяет записи на подготовленный слой `clean` (`6827` строк с числовыми типами `Int64`/`float`) и `quarantine` (`3` строки с исходными значениями и столбцом `reason`), проверяя баланс через `assert audit["input"] == audit["replays"] + audit["clean"] + audit["quarantine"]` (`6832 == 2 + 6827 + 3`, `parse_errors = 2`).

## H3 Проверка года и виды проблем

Как обнаружено нарушение года:
- В независимой копии `wrong_year = export.copy(deep=True)` значение `activity_year` первой строки изменено на `"2022"`. Выражение `wrong_year["activity_year"].eq("2023").fillna(False).all()` вернуло `False` (`assert year_check is False`), так как `fillna(False)` трактует возможные пропуски как непрохождение правила, а `.all()` требует истинности во всех строках. Исходный `export` не изменился (`assert_frame_equal(export, original_export)`).

Исходный пропуск, новая ошибка преобразования, необычная сумма — примеры и реакции:
- **Исходный пропуск (`NaN`):** Значение отсутствовало в файле изначально. *Пример:* в `clean` строки `source_row = 99` (`loan_amount = 205000.0`, `income = NaN`), `source_row = 103` (`loan_amount = 3005000.0`, `income = NaN`). *Реакция:* для необязательного поля `income` это норма — запись остаётся в `clean` со значением `NaN`.
- **Новая ошибка преобразования (`parse_error`):** В ячейке записан нечисловой текст, который не удалось прочитать числом. *Пример:* `source_row = 2` (`loan_amount = "oops"`, причина: `"некорректная сумма кредита"`) и `source_row = 5` (`income = "BAD"`, причина: `"некорректный доход"`). *(Также в карантин по правилу допустимых кодов попала `source_row = 3` с `action_taken = "88"`).* *Реакция:* фиксируется в `audit["parse_errors"]` (`2`), строка направляется в `quarantine` с сохранением исходного текста и описанием в `reason`.
- **Необычно большая числовая сумма:** Формат числа и правила не нарушены, но значение аномально велико. *Пример:* в `clean` строки `source_row = 326` (`loan_amount = 57005000.0` USD), `source_row = 1781` (`loan_amount = 40005000.0` USD), `source_row = 112` (`loan_amount = 6865000.0` USD). *Реакция:* строка проходит в `clean`, но выделяется фильтром (`loan_amount > 5_000_000`) для отдельной смысловой проверки по существу поля.
