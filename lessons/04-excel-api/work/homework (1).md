## H3 Покрытие записей и организаций

Результаты, проверки и объяснение:
Выполнено левое соединение `decisions` (6830 строк) с `home_lookup` (3 организации) с контролем `validate="many_to_one"`, сохранность всех исходных столбцов и значений `decisions` подтверждена через `assert_frame_equal`[cite: 4, 6, 11]. Покрытие по ипотечным записям составило `76 / 6830` ($1.11\%$), а покрытие по уникальным организациям (LEI) — `3 / 314` ($0.96\%$); все четыре счётчика и обе доли сохранены в `../results/homework/coverage.json`[cite: 6, 11]. Разница единиц измерения заключается в том, что покрытие по записям взвешено по объёму потока заявок (оценивает долю решений, для которых подтянулись атрибуты банка), тогда как покрытие по организациям считает каждую кредитную организацию с равным весом независимо от числа её заявок. Частичный охват ($\approx 1\%$) объясняется тем, что в выгрузку GLEIF сознательно запрашивались только первые 3 детерминированно выбранных кода LEI из 314 банков, представленных в `decisions.csv`[cite: 6].

## Передача

Файлы, определения, вывод и ограничения:
В состав сдачи входят воспроизводимый ноутбук `work/homework.ipynb` (проверенный через `Restart Kernel → Run All`), отчёт `work/homework.md` и пакет `../results/homework/` (`manifest.json`, `lookup.csv`, `coverage.json` и папка `raw/` с `gleif_page_01.json` и `gleif_page_02.json`)[cite: 6, 11]. В расчётах единицей таблицы `decisions` является одна ипотечная заявка, единицей `home_lookup` — одна организация с 20-значным ключом `lei`, покрытие записей определяется как `matched_records / total_records`, а покрытие организаций — как `matched_lei / total_lei`[cite: 6, 11]. По результатам пагинации GLEIF API собраны все 3 целевые организации, которые покрывают `76 / 6830` ($1.11\%$) заявок и `3 / 314` ($0.96\%$) организаций из ипотечного набора данных[cite: 6, 11]. Функция `collect_pages` останавливает обход с исключением `ValueError` в пяти защитных случаях: при зацикливании ссылки `next` на уже посещённый URL, если `data` не является списком, при изменении `meta.pagination.total` между страницами, при превышении лимита `max_pages` до исчерпания `next`, а также при дублировании `id` или несовпадении итогового числа записей с `expected_total`[cite: 4, 11]. Главным ограничением полученного справочника является временной сдвиг: `gleif_lookup` представляет собой текущий снимок реестра от октября 2026 года, поэтому его атрибуты нельзя использовать как признаки в моделях прогнозирования исходов 2023 года без проверки исторической доступности[cite: 6].

## Уточнённый вопрос проекта

Вопрос, данные, смысл строки, показатель, ограничение, следующий шаг и учтённая обратная связь:
Уточнённый исследовательский вопрос: как различается доля отказов по ипотечным заявкам в округе Колумбия за 2023 год между кредитными организациями в зависимости от объёма их заявок и доступного размера выборки? Для ответа используются таблица заявок `decisions.csv` (6830 записей за 2023 год) и справочник кредиторов `organizations.csv` (470 организаций, из которых 314 имеют решения в выборке), обогащаемый при необходимости данными GLEIF. Смысл одной строки в базовой таблице `decisions` — одно рассмотренное ипотечное заявление (`source_row`) с кодом исхода `action_taken`, а после агрегации — один кредитор в 2023 году `(lei, activity_year)`. Основной целевой показатель — доля отказов `denial_rate = n_denied / n_decisions` (отношение числа заявок со статусом `3` к общему числу решений организации), дополняемая общим покрытием справочника. Ключевые ограничения: данные охватывают только один календарный год и один регион (`county_code = 11001`), а внешний реестр GLEIF зафиксирован на октябрь 2026 года (возможна утечка будущих изменений статуса/названия при ретроспективном анализе)[cite: 6]. Следующий шаг — проанализировать связь доли отказов с суммой кредита (`loan_amount`) и доходом заявителя (`income`) на подвыборке организаций с устойчивым числом заявок (`n_decisions >= 20`)[cite: 8, 9]. По обратной связи в постановку добавлены явная фиксация единицы наблюдения (строки), разграничение взвешенной и невзвешенной долей, а также контроль временной актуальности справочных источников.
